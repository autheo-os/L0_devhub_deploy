Dependency licenses are compatible with commercial, proprietary distribution. No dependency requires DevHub’s own source to be released. The only copyleft is weak and file- or library-scoped:

  • libvips (LGPL-3.0+), loaded dynamically by the image library sharp;
  • attohttpc (MPL-2.0), a Rust crate.

Both are used unmodified.

The only Vercel-authored code in the repository is a byte-identical copy of the Apache-2.0 Vercel Workflow UI. It is pinned to an exact upstream commit and ships with its license. The package named @openedge/vercel-sdk is not Vercel code: it is an independent client that only mirrors the upstream constructor shape.

Open items for counsel:

  1. Ownership: the repository’s own license names Shadow Company / Dylan J. Wong as owner, and Autheo’s rights need a written assignment or license grant.
  2. Third-party service terms, chiefly the Vercel DNS API.
  3. An AGPL component that exists only in the separate upstream “shadow” repository, not in DevHub.

How the license classes are defined

  • permissive: MIT, BSD, ISC, Apache-2.0, Zlib, Unlicense and similar.
  • permissive choice: dual-licensed packages where at least one option is permissive. For example, Apache-2.0 OR GPL-2.0-only is used under Apache-2.0.
  • permissive + notice: permissive licenses with an attribution or data notice, such as Unicode-3.0, CC-BY-4.0, OFL, Python-2.0 and BlueOak.
  • weak copyleft: LGPL or MPL, which apply only to that library or file.

Weak-copyleft items and what they require

  • @img/sharp-libvips-*, @img/sharp-* (LGPL-3.0-or-later): the prebuilt libvips image library used by sharp, which Next.js uses for image optimisation. It is loaded dynamically and used unmodified, which LGPL permits in proprietary software. Keep its license text with any redistribution, and do not statically link or modify it.
  • attohttpc 0.30.1 (MPL-2.0): file-level copyleft. Unmodified use carries no obligation beyond the notice. Any change to its own files must stay under MPL-2.0.

Ownership of DevHub itself

The repository’s LICENSE.md is a proprietary license:

  • It names “Shadow Company / Dylan J. Wong” as owner.
  • It grants only limited internal use.
  • It forbids modification, redeployment as one’s own service, sublicensing and distribution.

Section 7 was added to make clear that those terms cover only original work, and that third-party components keep their own licenses. The Rust crate metadata, which previously said MIT, now points at LICENSE.md.

Dylan J. Wong has given Autheo permission to use DevHub. The permission is not yet written down. To modify, operate and sell DevHub, Autheo needs a signed assignment or a perpetual, irrevocable license grant covering the following rights:

  • use, modification and deployment;
  • sublicensing and sale;
  • work by the other contributors, confirming it is owned by the licensor.

The upstream “shadow” repository

DevHub is a fork of dywongcloud/shadow. The upstream repository has the same dependency profile and one significant addition that DevHub does not contain: vendor/node-worker.

  • It is licensed AGPL-3.0-only.
  • It has been modified.
  • Its build is served to every browser that uses shadow’s browser-node feature.

Pull requests against shadow add the missing license files and a notice for it. Whether code loaded alongside it counts as a separate work is a question for counsel before shadow itself is sold or relicensed.
